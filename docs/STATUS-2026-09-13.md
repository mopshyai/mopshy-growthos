## Supabase security notes

The GrowthOS tables use RLS and currently rely on trusted server-side/service-role access from n8n. The Supabase advisor reports informational `RLS Enabled No Policy` findings for GrowthOS tables because no browser/user policies are defined. That is compatible with the current internal-service architecture, provided service credentials remain server-side only.

The same Supabase project also contains a separate group of media-production tables (`workspaces`, `projects`, `shots`, `takes`, `renders`, etc.). Those objects were not changed during this activation. Keep future GrowthOS migrations scoped carefully so unrelated media-system tables are not modified accidentally.
